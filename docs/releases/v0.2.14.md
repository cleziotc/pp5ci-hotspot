# N0CALL Hotspot v0.2.14

Qualidade de rede dinâmica para Callsign Routing.

## Chamada direta

Durante uma chamada direta D-STAR, o N0CALL Hotspot passa a medir o gateway remoto associado ao indicativo pelo ircDDB em vez de continuar medindo o reflector linkado.

Exemplo:

- chamada direta: N0CALL → PY2ABC;
- ircDDB resolve o gateway remoto de PY2ABC;
- o card muda para **Qualidade da Rede (Chamada Direta)**;
- o indicativo e o IPv4 do gateway remoto aparecem no cabeçalho;
- latência, jitter, perda e barras passam a usar esse destino.

## Retenção de 60 segundos

Após a chamada direta:

- o destino remoto continua sendo monitorado por 60 segundos;
- uma nova chamada direta renova o prazo;
- uma nova chamada direta para outro indicativo troca imediatamente o alvo;
- qualquer tráfego de reflector cancela a retenção e devolve o card ao reflector;
- sem novo tráfego, ao final dos 60 segundos o card volta ao reflector conectado.

A mesma regra vale para chamadas diretas recebidas.

## Descoberta do IP

O DStarGateway possui suporte nativo a log de tráfego ircDDB. A v0.2.14 habilita `logIRCDDBTraffic=true` e o collector passa a armazenar os registros `USER:` em cache de memória.

O endereço usado é o gateway D-STAR remoto selecionado pelo ircDDB/G2 para alcançar o indicativo. Não é necessariamente o IP do rádio ou hotspot pessoal do operador.

## Medição

- método: TCP connect/refused;
- ICMP/ping não é necessário;
- portas tentadas para o gateway direto: 40000, 443, 80 e 22;
- timeout curto para evitar bloquear a coleta;
- nenhum pacote D-STAR adicional é gerado.

## Migração

Instalações existentes recebem automaticamente a opção `logIRCDDBTraffic=true`. O DStarGateway é reiniciado somente se a configuração precisar mudar.

## Segurança operacional

- MMDVMHost não é modificado;
- RF e vocoder não são alterados;
- histórico existente é preservado;
- a tabela de rede recebe apenas uma coluna aditiva para identificar o callsign das amostras diretas.
